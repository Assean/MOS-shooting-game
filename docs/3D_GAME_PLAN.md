# MOS 3D 競技場：系統規劃

## 目前可用的第一個 3D 里程碑

- Three.js WebGL 場景：有陰影、霧效、地面、邊界、霓虹能量柱與可辨識的競技場配置。
- 第一人稱桌面操作：點擊競技場鎖定滑鼠；W 向前、S 向後、A 向左、D 向右，滑鼠轉向、左鍵射擊、Esc 解除鎖定。
- 多人視覺同步：既有 WebRTC DataChannel 每 50ms 傳送座標、朝向與房內狀態；遠端玩家以 3D 機甲與名牌呈現。
- 戰鬥原型：可靠通道同步 Hitscan、物理電漿拋射物與淘汰事件；命中三次重生。Hitscan 使用 `Raycaster` 計算障礙物阻擋；拋射物受重力與場景碰撞影響。
- 操作與武器回饋：Pointer Lock 滑鼠鎖定、衝刺動態 FOV、向量／四元數鏡頭與槍械後座力、動態散射（Bloom）與彈著群。
- 碰撞與網路：玩家以圓形碰撞體與多個 AABB 掩體組成複合碰撞；本機保留 750ms 位置歷史，接收射擊時以時間戳作**客戶端回溯**。
- 設定：效能／平衡／畫質三段畫質預設、65–95 度視野設定，均保存在瀏覽器本機。

## 架構

```text
瀏覽器（Three.js/WebGL）
  ├─ UI：房間、名單、畫質、視野
  ├─ Client simulation：輸入、相機、場景、預測
  ├─ WebRTC state channel：不可靠、不排序，20Hz 座標與朝向
  └─ WebRTC event channel：可靠，射擊與淘汰事件
          │
Cloudflare Worker + Durable Object：WebSocket 協商
Cloudflare D1：玩家資料（不接受瀏覽器上傳戰績）
```

## 接下來的製作順序

1. **可玩性**：加入碰撞體、掩體不可穿透、命中射線與武器後座力；移動遠端玩家採插值，避免 20Hz 同步時抖動。
2. **對戰系統**：倒數、分數目標、回合結算、出生點規則、擊殺資訊與本局戰績面板。
3. **內容**：GLB 角色／武器模型、音效、材質、第二張地圖與地圖輪替。
4. **網路與安全**：以專用權威遊戲伺服器驗證移動、命中與比分；加入 TURN 中繼、區域選擇與連線品質指標。
5. **發行品質**：行動版觸控控制、無障礙設定、資源載入畫面、錯誤回報、效能預算與端對端多人測試。

## 延遲補償的安全界線

目前的回溯只用於 P2P 原型視覺與手感：射擊訊息帶有瀏覽器時間戳，受擊端會從最近 750ms 的本機位置歷史挑選最接近的樣本。裝置時間可能不同，且任一玩家都能竄改訊息，因此它**不能**作為正式競技判定。

正式版必須由權威伺服器保存每位玩家的快照歷史、使用伺服器時間判定射擊、驗證武器射速與彈道，並只由伺服器廣播傷害／擊殺結果。

## 非功能性目標

| 項目 | 原型目標 | 發行前方向 |
| --- | --- | --- |
| 操作更新 | 60 FPS（依裝置調整像素比） | 60 FPS，低階裝置 30 FPS 模式 |
| 狀態同步 | 20Hz P2P | 20–30Hz 伺服器權威快照 |
| 房間規模 | 2–4 人 | 依伺服器模擬與頻寬預算決定 |
| 戰績可信度 | 不可信、僅本局同步 | 僅權威伺服器寫入 |

## 部署與驗收

1. 使用兩台裝置，加入相同 Worker URL 與房間碼。
2. 兩端分別點擊競技場，確認滑鼠鎖定與第一人稱移動。
3. 驗證彼此可看見 3D 玩家、朝向與射擊軌跡；命中三次後另一端可見重生與計分更新。
4. 切換三種畫質與視野值，重新整理後設定仍在。
5. 檢查 `GET /api/health`，並以不同網路測試 P2P 連通性。
